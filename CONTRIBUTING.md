# Contributing

Thank you for taking the time to contribute to this project.

I welcome bug reports, documentation improvements, small fixes, and well-scoped feature proposals. I want to keep this project practical, maintainable, and easy to review, so I ask contributors to follow the guidance below before opening an issue or pull request.

## Before You Start

Please take a moment to review:

- the `README.md` for project overview and setup
- the `LICENSE` file for licensing terms
- the [CODE_OF_CONDUCT.md](./CODE_OF_CONDUCT.md) for community expectations
- existing issues and pull requests to avoid duplicates

## What Kind of Contributions I Accept

I generally welcome:

- bug fixes
- documentation improvements
- test improvements
- small refactors that improve clarity or maintainability
- focused new features that fit the scope of the project

I may decline contributions that:

- do not fit the direction of the project
- add large maintenance cost
- introduce unnecessary complexity
- duplicate existing work
- create legal, licensing, security, or support concerns

## Discuss First for Large Changes

If you want to propose a large change, please open an issue first before spending significant time on implementation. This helps me confirm whether the change fits the project before you prepare a pull request.

## How to Contribute

### Reporting Bugs

When opening a bug report, please include:

- what happened
- what you expected to happen
- steps to reproduce the issue
- your environment details when relevant
- logs, screenshots, or sample output when helpful

### Suggesting Features

When suggesting a feature, please describe:

- the problem you want to solve
- why the change would be useful
- possible alternatives you considered
- any compatibility or maintenance impact

### Submitting Pull Requests

Please try to keep pull requests:

- focused on one topic
- small enough to review clearly
- consistent with the existing style of the project
- accompanied by tests or documentation updates when needed

If possible, include:

- a short summary of the change
- the reason for the change
- any related issue number
- notes about trade-offs or limitations

## Development Expectations

Unless there is a strong reason not to, please:

- follow the existing code style and structure
- keep changes as small and clear as possible
- update documentation when behavior changes
- add or update tests when practical
- avoid unrelated cleanup in the same pull request

Before opening a pull request, please run:

- `npm run compile`
- `npm run lint`
- `npm test`
- `npm run security:check`

## AI-Generated Contributions

AI-assisted coding is allowed in this project.

However, by submitting AI-assisted or AI-generated code, text, tests, documentation, or other material, you confirm that:

- you reviewed the contribution yourself
- you understand the content you are submitting
- you have the right to submit it
- the contribution does not knowingly infringe any third-party rights
- the contribution is suitable for this repository's license and contribution rules

I review all contributions in my own judgment. I may reject any contribution, including AI-assisted contributions, for quality, maintainability, legal, licensing, originality, security, or project-fit reasons.

Use of AI does not reduce the contributor's responsibility for the submission.

## Licensing of Contributions

By submitting a contribution to this repository, you agree that your contribution is provided under the same license as this project, which is the MIT License, unless I explicitly state otherwise in writing.

You also represent that:

- the contribution is your original work, or you otherwise have the legal right to submit it
- you are permitted to make the contribution available under the project's license
- the contribution does not knowingly violate the rights of any person or third party

If you are contributing on behalf of an employer or another organization, you are responsible for ensuring that you have permission to do so.

## Review and Merge Policy

I review contributions based on my own judgment and the needs of the project.

Opening an issue or pull request does not create any obligation for me to respond, review, merge, release, maintain, or support the proposed change. I may close or decline contributions that are not a good fit, including cases where I do not provide detailed legal analysis or extended discussion.

## Code of Conduct

Please be respectful and constructive in all project interactions.

The [CODE_OF_CONDUCT.md](./CODE_OF_CONDUCT.md) applies to all community interactions related to this project.

## Security Issues

Please do not open a public issue for security vulnerabilities.

Please follow [SECURITY.md](./SECURITY.md) for the reporting process.

## Questions

If you are unsure whether a contribution is a good fit, please open an issue first and ask before starting work.

Thank you again for your interest in improving this project.
